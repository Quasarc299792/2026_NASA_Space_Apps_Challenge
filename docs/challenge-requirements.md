## 1. 背景（題目想解決的問題）
- 太空任務是一個系統：科學目標、工程需求、資源和操作限制要一起運作。
- 設計任務要決定太空船、科學儀器、火箭、軌道、功率、質量、通訊、預算、任務壽命。一個面向變好，常常會讓另一個面向受限。例如儀器更強，科學價值提高，但質量、功耗、資料量和成本也跟著增加。
- 現況的問題：學生很少有機會從概念到營運完整模擬一次任務。現有工具多半只處理單一主題（軌道力學、太空船設計或火箭發射），沒有呈現這些元素怎麼互相影響。
- 互動遊戲能讓玩家實驗、做決策、碰到限制，並從成功和失敗中學習。玩家可以單人玩，也可以最多 4 人組隊。

## 2. 目標（Objectives）
做一個**互動式太空任務設計遊戲**，讓玩家體驗設計並管理一個**完整**太空任務的過程。

遊戲可以讓玩家：
- 定義任務目標
- 訂定任務需求
- 設計太空船
- 選擇科學儀器
- 選擇運載火箭和軌道
- 管理關鍵限制：預算、質量、功率、通訊、資料、任務壽命

玩家要能看到自己的決策怎麼影響任務的其他部分，並理解真實任務設計中的 trade-off。

**強解法（A strong solution）可能包含：**
1. 可運作的互動遊戲或模擬，介面清楚
2. 任務配置系統
3. 資源管理機制
4. 最多 4 人的協作或多人功能
5. 任務模擬與評估系統

遊戲應該針對任務表現給回饋，並獎勵這些行為：好的工程決策、有效率的資源管理、成功的協作、達成任務目標。
鼓勵設計有創意的遊戲機制、視覺化、計分系統和任務情境，讓玩家必須解決問題、做 trade-off，並協作完成任務。

## 3. 可考慮的項目（Potential Considerations，全部列出）

### 3.1 遊戲設計與體驗
- 對太空科學和工程程度不同的玩家都要容易上手。
- 支援單人和團隊模式（最多 4 人合作完成同一個任務）。
- 隊員可以有不同職責：任務規劃、太空船設計、科學、通訊、資源管理。
- 目標和回饋要清楚，讓玩家知道任務**為什麼**成功或失敗。
- 互動性：玩家可以修改設計、多次模擬。
- 計分系統獎勵：任務成功、科學價值、資源使用效率、好的決策。
- 可以有不同的難度、任務類型或情境。

### 3.2 任務設計
- 玩家先定義任務目標，再做太空船和工程決策。
- **每個重大決策都要有後果**（例如儀器越多，科學能力越強，但質量、功耗、成本、資料量也增加）。
- 呈現「**幾乎沒有唯一完美解**」：不同的太空船、儀器、軌道、火箭組合都可能達成同一個目標。
- 加入真實限制：有限的預算、質量、功率、通訊容量、任務壽命。

### 3.3 太空船與酬載
- 元件可以包括：結構、電力系統、電池、通訊、星載電腦、姿態控制、科學儀器。
- 儀器有不同屬性：質量、功耗、成本、資料產生量、科學價值。
- 可以依難度提供簡易版或進階版元件。

### 3.4 軌道與發射
- 提供數種軌道選項，並說明各自的基本特性。
- 軌道會影響：覆蓋範圍、觀測機會、通訊、任務壽命和其他需求。
- 火箭有不同的酬載能力、成本和可達軌道。
- **要檢查太空船質量和所選軌道跟火箭是否相容。**

### 3.5 資源管理
遊戲應**清楚顯示**主要資源：
- **Mass 質量**：太空船加酬載的總質量
- **Power 功率**：系統和儀器可用的能量
- **Budget 預算**：開發和營運經費
- **Data 資料**：儀器產生的資料量
- **Communications 通訊**：傳資料回地面站的能力
- **Time 時間**：規劃的開發期和營運壽命
- 可以標出對該任務最關鍵的是哪些資源。

### 3.6 協作
- 團隊模式最多 4 人合作同一個任務。
- 隊員有不同角色或職責，但要**共同決策**。
- 可以設計**隊員之間必須協商、優先順序互相衝突的情境**。
- 最終結果取決於團隊協調得好不好。

### 3.7 教育價值
- 用簡單的方式解釋科學和工程概念，不要假設玩家有進階知識。
- 軌道高度、酬載能力、功耗、資料率、通訊等複雜概念，透過遊戲本身來教。
- 可以加短說明、教學、視覺指標或延伸學習資源。
- **要教玩家「為什麼」這個決策影響任務表現，而不是只告訴他對或錯。**

### 3.8 可加入的功能（清單）
- 多種任務情境，目標各不相同
- 隨機事件或意外的任務限制
- 不同難度
- 真實或簡化的太空船模型
- 互動式太空船視覺化
- 即時顯示資源消耗的任務儀表板
- 排行榜或任務排名
- 每次模擬結束後產生任務報告
- 儲存、分享、比較任務設計
- 最多 4 人的合作任務
- **競賽情境：不同隊伍設計任務來解決同一個目標**（也就是 PK）
- 沙盒模式：沒有預設限制，自由實驗
- 任務後分析：解釋任務成功或失敗的原因

## 4. 題目提供的資源（Resources）
**NASA 資料與資源**
- **Design and Develop Science Missions**：科學任務的系統工程流程（從科學需求到需求定義、設計、驗證、實作）。四大區段：Launch（發射）、Space（太空船、儀器）、Ground（地面站、任控）、User（使用資料的科學家）。
- **GMAT（General Mission Analysis Tool）**：開源任務分析軟體，可做 LEO、GEO、HEO、月球、拉格朗日點、行星際轉移等軌道傳播、最佳化、發射窗口分析、機動規劃。
- **Concept Maturity Levels（CMLs）**：JPL 的任務概念成熟度框架，CML 1（初步想法）到更詳細的等級，重點在 CML 1–4。
- **Mission Design Lab（MDL）**：NASA 的協作任務設計環境。研究層級：Office Hours → Concept Development → Trade Studies → Point Design。涵蓋軌道、太空船、通訊、地面系統、火箭、營運、任務結束規劃，以及電力、推進、熱控、結構、航電、通訊、姿態控制、軟體、可靠度、成本、風險。
- **NASA Mission Viz**：網頁版 3D 任務軌道視覺化。
- **A Learning Game About Telescopes**：NASA 的教育遊戲，玩家設計太空望遠鏡：選科學目標 → 選波段、儀器、光學 → 發射動畫 → 結果 → 對照相似的真實 NASA 任務。共三個難度等級。（**可以直接當參考範例**）
- **CubeSat 101**：CubeSat 任務各階段的基本概念（ConOps 到發射和營運）。
- **Visualize a Space Mission Using VR**：2023 年的 Space Apps 題目，用 VR 視覺化整個任務（概念、軌道、時間軸、3D）。

**太空機構夥伴資源**
- CSA（加拿大太空總署）Digital Games and Activities：數位遊戲、電子書、影片、動手做活動。

## 5. 提交規則（硬性規定）
- **團隊**：1–6 人（Universal Event 至少 2 人）。所有人都要報名同一個 Local Event（不能在候補名單），並出現在隊伍頁的 Members 分頁。截止後不能加人。每人只能加入一隊，每隊只能做一題。
- **語言**：提交頁和所有連結的資料都**必須是英文**。影片可以講中文，但**必須有英文字幕**；簡報一定要英文。
- **Demo（必交）**：二選一
  - 影片 **≤ 30 秒**，或
  - 簡報 **≤ 7 頁**（含標題頁和介紹頁）
  - **超過限制就沒有資格進入 Global Judging。**
  - 上傳到 YouTube、Google Drive、GitHub 等，連結要**公開，不需要登入或權限**（用無痕視窗測試）。
- **Project 頁面要填的欄位**：
  1. Project Name
  2. High-Level Project Summary（做了什麼、怎麼回應題目、為什麼重要）
  3. Link to Project Demo
  4. Link to Final Project（網站或 GitHub 等，公開連結）
  5. Detailed Project Description（做什麼、怎麼運作、好處、目標、用了哪些工具和語言）
  6. Use of Super Intelligence（SI＝AI，見下方）
  7. **NASA Data：要拿 Global Award，至少要用 1 個 NASA 資料或資源。**
  8. Space Agency Partner Data and Other References：列出**所有**用到的程式碼、文字、圖片（開源或免費的也要列）。有版權的素材要有授權。
- 頁面可以上傳圖片（JPG、PNG、GIF，≤10MB），影片和文件只能用連結。
- 自架網站的話，建議申請 FortiGuard Web Filter Classification，避免評審連不上（不是必要）。
- 提交時要勾兩個同意框：已讀規則和條款；作品是原創，所有外部資源都已列在 References。

### SI（AI）使用規定
- 可以用 AI 工具（LLM、程式碼產生、圖片產生等）來加速開發。
- **但 SI 不應該被用來想出「怎麼解這個題目」的點子。**
- 產生的內容不能使用、包含或修改 NASA 品牌元素（logo、旗幟、任務標識）。
- 要標示：AI 圖片和影片要加**可見浮水印**；AI 音訊、程式碼、資料要在說明文字和 metadata 註明。
- 評審看不到 SI 問卷的回答，但看得到作品裡的 AI 標示，會據此評估原創性。

## 6. 評分標準（每項 1–5 分）
| 項目 | 看什麼 | 對本題的意義 |
|---|---|---|
| **Impact 影響力** | 解決的問題有多重要、能幫到多少人 | 太空教育、讓一般人理解任務設計 |
| **Creativity 創意** | 原創性、是否改良既有做法 | 機制要有新意（例如人生模擬器式的事件和結局、PK） |
| **Validity 有效性** | 科學原理正確、技術可行、完成度、好不好用 | **物理要對**（Δv、功率、link budget），可以用 GMAT 驗證；要能實際玩 |
| **Relevance 切題** | 完整回應題目、**NASA 資料是核心而不是點綴** | 用上 GMAT、真實任務參數、NASA 火箭和儀器資料 |
| **Presentation 呈現** | 說故事能力、Demo 是否清楚吸引人 | 官方特別提醒這項常被忽略；Demo 也算進這項分數 |

官方 30 秒影片的建議結構：
- [0:00] 自我介紹和隊名
- [0:02] 選了哪一題、為什麼
- [0:05] 專案名稱和 tagline
- [0:10] 怎麼運作、使用者體驗，以及 NASA 資料怎麼讓它成真
- [0:20–0:30] 未來願景

7 頁簡報要包含：隊名、隊員名字、選的題目、專案畫面、使用者體驗、NASA 資料怎麼被使用。
