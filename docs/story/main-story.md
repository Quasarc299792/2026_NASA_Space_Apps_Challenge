# FINAL ORBIT／最後的軌道

## 角色

| 角色 | 在故事裡負責的事 |
| --- | --- |
| 玩家，Astra Dynamics 的任務負責人 | 選擇任務、核定工程方案，依審查結果決定放行並承擔簽署的風險。 |
| Alex Morgan，專案營運 | 管經費、工期和出資方的承諾。兩年前他提醒團隊，延期可能讓公司拿不到下一期款。 |
| Elena Carter，首席系統工程師 | 解讀測試、指出證據缺口。她在事故前建議暫停，事故後離開，收到新委託後回來。 |
| Samuel Reed，政府太空計畫聯絡人 | 轉達使用者需要的成果，引介委託與合作方。 |

多人審查的 PM 是房間內的玩家角色，職責見[多人合作草案](../multiplayer.md)。

## 序章與三份委託

兩年前，Astra Dynamics 第一次做入軌示範。任務負責人在間歇性航電警告未結案時批准發射，火箭起飛後失聯。調查未能確認失效原因，投資人撤資。兩年後，政府原有的承包商趕不上交件，Samuel 找上即將關門的 Astra Dynamics。首章簡報可展開當年倒數和失聯的經過。

| 章節 | 委託與工程抉擇 | 劇情接點 |
| --- | --- | --- |
| 第一道曙光 · First Light | 從[洪災通行圖或海灣排水調查](../story-cubesat.md#7-首局委託版處理狀態)選一份。確認地面團隊要收到什麼，再安排搭載、主儀器、轉向餘裕與副感測器。追加觀測在基本資料交付、通聯和拍攝皆有餘裕時出現。 | Elena 回來看整合報告。交付成功後出資方才提出入軌邀約。 |
| 再一次入軌 · Second Attempt | [入軌示範](orbital-launch.md)需要把測試酬載送進合約軌道，並交付確認資料。經費削減後要重新比較方案和剩餘工作。 | Elena 在簡報翻出舊放行紀錄。地面資料鏈真的測出異常時才出現對話。飛行審查列出當局的驗證證據與需要簽署的風險。 |
| 月球委託 · Lunar Contract | [登月計畫](lunar-mission.md)需要抵達月面並交付可用資料，供科學團隊選擇下一輪製圖區域。開局談合作，依合約狀態與事件處理發表日期、第二酬載等交換條件。 | 既有飛行七段和應變選項呈現設計後果。終章在結算顯示，完成交付才收到下一案，未放行、飛行中斷或交付不足仍保留對應紀錄供重玩。 |

## 跨章條件與履歷

- 初始只開放立方衛星。完成當前委託的最低要求才解鎖下一份。已解鎖的任務可以重玩。
- 立方衛星的合作整合驗證和交付可換入軌實驗室時段。入軌的準時交付、驗證紀錄和證實的運載餘裕，分別改善登月的預付款、技術支援及質量配額。
- 任務履歷保留各章最佳成果的配置、花費、工期、驗證檢查與交付量。成果相同時保留最近的一局。歷次取得的合作資格另外累積，聲望仍依各章最低和額外目標計分。舊存檔的成果與資格會保留，報告明細從新結算開始記錄。
- 當局結果、證據和完整決策紀錄留在各章結算。終章台詞以本次登月的交付為準，履歷則保留跨局已達成的成果。
